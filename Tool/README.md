# SFP 模块固件擦除工具 (CH341A I2C)

针对 `10G_DAC-ADuC7020 (KV0)` 固件（SFP 封装，SFF-8472 双地址 A0h/A2h）的 Host 端擦除工具，通过 CH341A USB 转 I2C 适配器向模块发送擦除命令。

## 使用方法

```bash
python ch341_erase_fw_tool.py
```

仅需 Python 标准库（tkinter + ctypes），无第三方依赖。

## 前置条件

1. **CH341 DLL**（WCH 官方 CH341PAR 驱动，本目录 `Tool\CH341PAR` 已自带驱动包）：
   - DLL 命名：32 位 = `CH341DLL.DLL`，64 位 = `CH341DLLA64.DLL`；
   - 工具按 PE 头位数自动匹配当前 Python，依次搜索：工具目录 → `Tool\CH341PAR\CH341PAR`（含 WIN 1X 子目录）→ `System32` / `SysWOW64`；
   - 若设备管理器里 CH341A 显示为串口（CH341SER 驱动），需改装 **CH341PAR** 驱动（运行 `Tool\CH341PAR\CH341PAR\SETUP.EXE`）后 I2C API 才可用。
2. **接线**：CH341A 的 `SCL / SDA / GND` 接模块的 `SCL / SDA / GND`，模块供电 3.3V。
3. **I2C 访问方式**：采用**字节级 API**（`CH341ReadI2C`/`CH341WriteI2C`，每字节一笔独立事务）。
   在 **CH341A3（芯片版本 0x30）+ 新版驱动** 的组合上，`CH341StreamI2C` 实测连地址探测都会失败，因此工具不使用它。
   注意：字节级 API 的返回值**不作 ACK 判断**（永远返回成功），在线判定以读回数据是否全 `0xFF` 为准。

## 擦除协议（对应固件 code/inttrupt.c、code/pubcom.h）

模块 I2C 从机地址：A0 页 = 0x50，**A2 页 = 0x51（擦除只用到它）**

| 步骤 | 器件 | 寄存器 | 写入数据 | 说明 |
|------|------|--------|----------|------|
| ① 解锁 | A2 (0xA2) | 123~126 | `75 75 61 61`（"uuaa"） | 写入 126 时触发密码校验，须按顺序、126 最后写 |
| ② 选页 | A2 | 127 | `00` | 选择上页 Page00 |
| ③ 擦除 | A2 | 250~253 | `65 72 61 73`（"eras"） | **写入 253 最后一个字节的瞬间固件关中断并整片自擦** |

I2C 时序（写密码步骤，逐字节独立事务）：

```
START  A2 7B 75 STOP        ; 寄存器123 ← 'u'
START  A2 7C 75 STOP        ; 寄存器124 ← 'u'
START  A2 7D 61 STOP        ; 寄存器125 ← 'a'
START  A2 7E 61 STOP        ; 寄存器126 ← 'a' (此刻固件校验密码)
```

每字节独立事务、寄存器地址显式携带，与固件中断处理逻辑（`inttrupt.c:546-575`）一致，不依赖地址自增。

## 擦除结果判定

- 擦除命令的最后一个字节（寄存器 253 ← 's'）落笔时固件立即关中断自擦，该字节事务可能无正常应答——**属正常现象**；
- 擦除后复测读 A2 寄存器 0-3：**读回全 0xFF = 擦除成功**（总线无应答）；有效数据 = 模块仍在线；
- 之后只能通过 **JTAG** 或 **UART 下载模式**（BM 引脚拉低复位进 BootLoader）重新烧写固件。

## 备注（KV0 固件特性）

- `code/inttrupt.c:528`：每次 I2C 中断入口强制 `glb_passward_enable = TRUE`，因此 KV0 固件实际可跳过密码步骤；工具仍默认执行完整三步以兼容其它批次。
- 工具内置二次确认弹窗，防止误擦。
